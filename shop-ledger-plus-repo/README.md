# 🏪 Shop Ledger Plus – บัญชีร้านค้า

เว็บบันทึก **รายรับ–รายจ่าย กำไร/ขาดทุน** สำหรับพ่อค้าแม่ค้า พร้อมเครื่องมือเสริมสำหรับร้านเล็กๆ
ทำด้วย HTML + CSS + JavaScript ล้วน **ไม่มี build step ไม่มี dependency** เปิด `index.html` ได้เลย
รองรับ **ภาษาไทย / English**, โหมดมืด, ใช้บนมือถือได้

> English: a vanilla-JS income/expense/profit tracker for small shops with stock, pricing, break-even,
> credit records, goals, sample data and backups. No build step, no dependencies. Thai + English UI.

## ✨ ฟีเจอร์

**หน้าหลัก**
- กำไร / รายรับ / รายจ่าย ตามช่วง *วันนี้ · เดือนนี้ · ปีนี้* พร้อมเทียบช่วงก่อนหน้า
- กราฟแท่ง/กราฟเส้น (สัปดาห์ / รายวันในเดือนที่เลือกได้ / 12 เดือน) แตะดูตัวเลขได้ + กราฟโดนัทสรุป
- เพิ่ม/**แก้ไข**/ลบรายการ รับเลขไทยและเลขมีลูกน้ำ (`1,250`, `๓๐๐`) · ไม่รับวันที่ในอนาคต · กด Esc ปิดหน้าต่าง · จำโหมดมืดไว้
- วงกลมสรุปแสดง **รายจ่ายและกำไรเป็น % ของรายรับ** (อัตรากำไรอยู่กลางวง) · วันที่ "วันนี้" อัปเดตเองเมื่อข้ามเที่ยงคืน
- เริ่มใช้งาน 2 แบบ: **ดูด้วยข้อมูลตัวอย่าง** หรือ **กรอกข้อมูลเองทั้งหมด** (ตัวช่วย 5 ขั้น: สินค้า → รายรับ → รายจ่าย → ลูกหนี้ → เป้าหมาย)

**ฟีเจอร์เสริม (แท็บ 🧰)** – ทุกแท็บมีแดชบอร์ดของตัวเอง
| แท็บ | ทำอะไร |
|---|---|
| 📦 สต็อก | เพิ่ม/**แก้ไข**/ลบสินค้า, ขาย/**ขายเชื่อ**/เติมสต็อก (ลงบัญชีให้อัตโนมัติ), แจ้งเตือนของใกล้หมด/หมด · ลบสินค้าแล้วประวัติและกำไรย้อนหลังไม่เปลี่ยน |
| 🧮 ต้นทุน/ราคา | คิดต้นทุนต่อชิ้นและราคาขายที่แนะนำจากกำไรที่ต้องการ |
| ⚖️ จุดคุ้มทุน | ต้องขายกี่ชิ้นต่อเดือน/ต่อวัน + กราฟรายได้ตัดต้นทุน |
| 🏆 ขายดี/ไม่ดี | จัดอันดับสินค้า, สัดส่วนยอดขาย, ยอดขาย vs กำไร, แนวโน้ม, วันไหนขายดี |
| 🤝 ลูกหนี้/เจ้าหนี้ | ติดตามหนี้ เกินกำหนด/ใกล้ครบ · **รับ/จ่ายทีละส่วนได้** · แก้ไขรายการหนี้ · หนี้จาก "ขายเชื่อ" ลงรายรับเมื่อลูกค้าจ่ายเงินจริง |
| 🎯 เป้าหมาย | เป้ายอดขายรายเดือน, ความคืบหน้า, คาดการณ์สิ้นเดือน |
| 🩺 ตรวจข้อมูล | หารายการที่ "ค้าง/กำพร้า" และรายการที่พิมพ์เองซึ่งไม่ผูกกับสินค้า (เชื่อมย้อนหลังได้) |
| 💾 สำรอง/ซิงค์ | ข้อมูลตัวอย่าง, รีเซ็ต, ไฟล์สำรอง `.json`, **รหัสย้ายเครื่อง**, ซิงค์ข้ามเครื่อง (เฉพาะเมื่อเปิดในแอป Claude) |

**ความถูกต้องของข้อมูล:** ขาย/เติมสต็อก/ชำระหนี้ ผูกกับรายการบัญชี ลบอันหนึ่ง **ทุกหน้าอัปเดตตาม** (คืนสต็อก, ลบประวัติ,
ย้อนสถานะหนี้) พร้อมหน้าต่างยืนยันที่บอกว่าจะเกิดอะไรบ้าง · ช่องตัวเลขปฏิเสธค่าติดลบ ตัวอักษร และเลขเกิน 100 ล้าน

## 🚀 เริ่มใช้งาน

```bash
# วิธีที่ 1: ดับเบิลคลิก index.html
# วิธีที่ 2: เปิดเว็บเซิร์ฟเวอร์ในเครื่อง
npx serve .          # แล้วเปิด http://localhost:3000
```

ข้อมูลเก็บใน **localStorage ของเบราว์เซอร์** (ไม่มีเซิร์ฟเวอร์ ไม่ส่งข้อมูลออกนอกเครื่อง)

### รวมเป็นไฟล์เดียว (ไว้ส่งงาน/แนบอีเมล)
```bash
node tools/build-single.js     # ได้ dist/shop-ledger-single.html เปิดได้ด้วยการดับเบิลคลิก
```

### เดโมออนไลน์ด้วย GitHub Pages
Settings → Pages → Deploy from branch → `main` / root แล้วเปิดลิงก์ที่ได้ (ต้องเป็น https ถึงใช้คลิปบอร์ดได้)

## 🧪 ทดสอบ
```bash
pip install playwright && playwright install chromium
python3 tests/smoke_test.py                              # ทดสอบ index.html
python3 tests/smoke_test.py dist/shop-ledger-single.html # ทดสอบไฟล์ที่ build
```
เทสต์วิ่งบน Chromium จริง (22 ข้อ): ข้อมูลตัวอย่าง, ขาย/ลบแล้วสต็อกคืน, ลบสินค้าแล้วประวัติไม่หาย, แก้ไขสินค้า/รายการ,
ปฏิเสธเลขติดลบและวันที่อนาคต, ขายเชื่อ + ชำระบางส่วน, ดาวน์โหลด-นำเข้าไฟล์สำรอง, ตัวช่วยกรอกเอง 5 ขั้น, Esc, จำธีม, สลับภาษา, ไม่มี JS error

## 🗂 โครงสร้าง
```
index.html            โครงหน้า (markup เท่านั้น)
css/style.css         สไตล์ทั้งหมด (ธีมธุรกิจ น้ำเงิน-ทอง, โหมดมืด, responsive)
js/                   สคริปต์ (โหลดตามลำดับเลขในไฟล์ ดู docs/ARCHITECTURE.md)
js/legacy/            โค้ดส่งออก Excel/PDF ที่ปิดไว้ (ไม่ถูกโหลด)
tools/build-single.js รวมทุกอย่างเป็นไฟล์ HTML เดียว
tests/smoke_test.py   เทสต์ end-to-end (Playwright)
docs/ARCHITECTURE.md  อธิบายโค้ด, ข้อมูล, ที่เก็บข้อมูล
```

## ⚠️ ข้อจำกัดที่ควรรู้
- ไม่มีระบบล็อกอิน/แชร์ข้อมูลระหว่างผู้ใช้ ข้อมูลอยู่ในเบราว์เซอร์ของแต่ละเครื่อง **ล้างเบราว์เซอร์ = ข้อมูลหาย** → ใช้ไฟล์สำรอง/รหัสย้ายเครื่อง
- ข้อมูลใน localStorage **ไม่ได้เข้ารหัส**; ไฟล์สำรองและรหัสย้ายเครื่องก็ไม่เข้ารหัส
- ซิงค์ข้ามเครื่องใช้ `window.claude` (db/user) ซึ่งมีเฉพาะตอนเปิดเป็น Artifact ใน Claude; เปิดจากไฟล์/GitHub Pages จะไม่มีซิงค์ (แอปทำงานปกติ แค่ปุ่มซิงค์แจ้งว่าใช้ไม่ได้)
- ถ้าอยากให้ซิงค์ได้ทุกคนจริงๆ ต้องมี backend ของตัวเอง (เช่น Firebase Auth + Firestore) ยังไม่ได้ทำใน repo นี้
- ส่งออก Excel/PDF ถูกปิดไว้ (ดู `js/legacy/README.md`)
- ระบบบัญชีเป็น **cash basis**: ขายเชื่อลงรายรับเมื่อได้รับเงินจริง ส่วนยอดขายใน "เป้าหมาย/จุดคุ้มทุน" นับเฉพาะรายรับจากการขาย (ไม่รวมรับชำระหนี้ที่ไม่ได้มาจากขายเชื่อ และรายรับอื่นๆ)
