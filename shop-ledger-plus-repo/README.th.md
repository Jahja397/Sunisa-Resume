# 🏪 Shop Ledger Plus – บัญชีร้านค้า

[🇬🇧 English](README.md) · 🇹🇭 **ภาษาไทย**

เว็บบันทึก **รายรับ–รายจ่าย กำไร/ขาดทุน** สำหรับพ่อค้าแม่ค้า พร้อมเครื่องมือเสริมสำหรับร้านเล็กๆ
(สต็อก ต้นทุนและราคา จุดคุ้มทุน ลูกหนี้/เจ้าหนี้ เป้าหมายยอดขาย)
ทำด้วย **HTML + CSS + JavaScript ล้วน ไม่มี build step ไม่มี dependency** เปิด `index.html` ได้เลย
รองรับภาษาไทย / English โหมดมืด และใช้บนมือถือได้ (ตรวจจอตั้งแต่ 320 ถึง 1280 px)

## ✨ ฟีเจอร์

**หน้าหลัก**
- กำไร / รายรับ / รายจ่าย ตามช่วง *วันนี้ · เดือนนี้ · ปีนี้* พร้อมเทียบช่วงก่อนหน้า
  (ถ้าไม่มีข้อมูลก่อนหน้าจะบอกว่า "ไม่มีข้อมูล" แทน ↑100% ปลอมๆ)
- กราฟแท่ง/กราฟเส้น: สัปดาห์ (จันทร์–อาทิตย์), รายวันในเดือน (เลือกเดือน/ปีย้อนหลังได้ เฉพาะกราฟ), หรือ 12 เดือน
  แตะ/ลากดูตัวเลขได้ มีเลขแกน Y
- วงกลมสรุป: **รายจ่ายและกำไรเป็น % ของรายรับ** อัตรากำไรอยู่กลางวง
- เพิ่ม / **แก้ไข** / ลบรายการ ช่องตัวเลขเข้มงวด: ไม่รับติดลบ ตัวอักษร เกิน 100 ล้าน หรือวันที่ในอนาคต
  แต่รับเลขไทยและเลขมีลูกน้ำ (`1,250`, `๓๐๐`)
- เริ่มใช้งาน 2 แบบ: **ดูด้วยข้อมูลตัวอย่าง** (ร้านข้าวมันไก่ 6 สัปดาห์) หรือ **กรอกข้อมูลเองทั้งหมด**
  (ตัวช่วย 5 ขั้น: สินค้า → รายรับ → รายจ่าย → ลูกหนี้ → เป้าหมาย)

**ฟีเจอร์เสริม (แท็บ 🧰)** – 8 แท็บ ทุกแท็บมีแดชบอร์ดของตัวเอง

| แท็บ | ทำอะไร |
|---|---|
| 📦 สต็อก | เพิ่ม/**แก้ไข**/ลบสินค้า, **ขาย** (ตัดสต็อก + ลงรายรับ), **ขายเชื่อ**, เติมสต็อก (ลงรายจ่าย), แจ้งเตือนของใกล้หมด/หมด |
| 🧮 ต้นทุน/ราคา | คิดต้นทุนต่อชิ้นและราคาขายที่แนะนำจากกำไรที่ต้องการ |
| ⚖️ จุดคุ้มทุน | ต้องขายกี่ชิ้นต่อเดือน/ต่อวัน + กราฟรายได้ตัดต้นทุน |
| 🏆 ขายดี/ไม่ดี | จัดอันดับสินค้า สัดส่วนยอดขาย ยอดขาย vs กำไร แนวโน้ม วันไหนขายดี |
| 🤝 ลูกหนี้/เจ้าหนี้ | ติดตามหนี้ เกินกำหนด/ใกล้ครบ **รับ/จ่ายทีละส่วนได้** แก้ไขรายการได้ |
| 🎯 เป้าหมาย | เป้ายอดขายรายเดือน ความคืบหน้า คาดการณ์สิ้นเดือน ต้องขายวันละเท่าไหร่ |
| 🩺 ตรวจข้อมูล | หารายการ "ค้าง/กำพร้า" และรายการที่พิมพ์เองซึ่งไม่ผูกกับสินค้า (เชื่อมย้อนหลังได้) |
| 💾 สำรอง/ซิงค์ | ข้อมูลตัวอย่าง รีเซ็ต ไฟล์สำรอง `.json` **รหัสย้ายเครื่อง** ซิงค์ข้ามเครื่อง (เฉพาะใน Claude) |

**ความถูกต้องของข้อมูล**
- ขาย/เติมสต็อก/ชำระหนี้ **ผูกกับรายการบัญชี** ลบอันหนึ่ง ทุกหน้าอัปเดตตาม (คืนสต็อก ลดยอดที่ชำระ ฯลฯ)
  พร้อมหน้าต่างยืนยันที่บอกชัดว่าจะเกิดอะไรบ้าง
- ลบ **สินค้า** = ลบเฉพาะตัวสินค้า ประวัติการขาย รายการบัญชี และกำไรย้อนหลังไม่เปลี่ยน
- **ขายเชื่อ** ตัดสต็อกและสร้างลูกหนี้ แต่ลงรายรับเมื่อลูกค้าจ่ายเงินจริง (บัญชีแบบ cash basis)
- ยอดขายใน "เป้าหมาย/จุดคุ้มทุน" นับเฉพาะรายรับจากการขาย (ไม่รวมรับชำระหนี้ที่ไม่ได้มาจากขายเชื่อ และรายรับอื่นๆ)
- เปิดแอปค้างข้ามเที่ยงคืนได้ วันที่ "วันนี้" อัปเดตเอง
- ทุกการนำเข้า/รีเซ็ต/ซิงค์เก็บสำเนาไว้ให้ **ย้อนกลับ** ได้ 1 ครั้ง

## 🚀 เริ่มใช้งาน

```bash
# วิธีที่ 1: ดับเบิลคลิก index.html
# วิธีที่ 2: เปิดเว็บเซิร์ฟเวอร์ในเครื่อง
npx serve .          # แล้วเปิด http://localhost:3000
```

ข้อมูลเก็บใน **localStorage ของเบราว์เซอร์** (ไม่มีเซิร์ฟเวอร์ ไม่ส่งข้อมูลออกนอกเครื่อง)

### รวมเป็นไฟล์เดียว (ไว้ส่งงาน/แนบอีเมล)
```bash
node tools/build-single.js     # ได้ dist/shop-ledger-single.html เปิดได้ด้วยการดับเบิลคลิก
```

### เดโมออนไลน์ด้วย GitHub Pages
Settings → Pages → Deploy from a branch → `main` / root แล้วเปิดลิงก์ที่ได้ (ต้องเป็น https ถึงใช้คลิปบอร์ดได้)

## 🧪 ทดสอบ
```bash
pip install playwright && playwright install chromium
python3 tests/smoke_test.py                               # ทดสอบ index.html
python3 tests/smoke_test.py dist/shop-ledger-single.html  # ทดสอบไฟล์ที่ build
```
เทสต์ 25 ข้อวิ่งบน Chromium จริง: ข้อมูลตัวอย่างครบทุกหน้า, ขาย/ลบแล้วสต็อกตรงกัน, ลบสินค้าแล้วประวัติไม่หาย,
แก้ไขสินค้า/รายการ, ปฏิเสธเลขติดลบและวันที่อนาคต, ขายเชื่อ + ชำระบางส่วน, ดาวน์โหลด→นำเข้าไฟล์สำรอง,
ตัวช่วยกรอกเอง 5 ขั้น, ปุ่ม Esc, จำธีม, สลับภาษา, ข้อความที่พิมพ์ไม่หายตอนซิงค์เบื้องหลังลองซ้ำ และไม่มี JS error

## 🔐 ความเป็นส่วนตัวและข้อมูล
- ข้อมูลทั้งหมดเก็บใน **localStorage ของเบราว์เซอร์** (คีย์ `ledger`, `plus`, `lang`, `theme` ฯลฯ)
  **ล้างข้อมูลเบราว์เซอร์ = ข้อมูลร้านหาย** จึงควรใช้ไฟล์สำรองหรือรหัสย้ายเครื่อง
- ข้อมูล ไฟล์สำรอง และรหัสย้ายเครื่อง **ไม่ได้เข้ารหัส**
- ไม่มีระบบล็อกอิน ใครใช้เบราว์เซอร์โปรไฟล์เดียวกันก็เห็นข้อมูลเดียวกัน

## ⚠️ ข้อจำกัดที่ควรรู้
- **ไม่รองรับหลายผู้ใช้ใช้ข้อมูลร่วมกัน** แต่ละเบราว์เซอร์มีข้อมูลของตัวเอง ถ้าอยากให้เจ้าของกับลูกจ้างใช้ชุดเดียวกัน
  ต้องมี backend ของตัวเอง (เช่น Firebase Auth + Firestore) ซึ่งยังไม่มีใน repo นี้
- **ซิงค์ข้ามเครื่องใช้ได้เฉพาะใน Claude** (ใช้ `window.claude` ฐานข้อมูล + ผู้ใช้ ผูกกับบัญชี Claude ที่ล็อกอิน และต้องมีสิทธิ์เขียน)
  เปิดจากไฟล์หรือ GitHub Pages ปุ่มซิงค์จะแจ้งว่าใช้ไม่ได้ ส่วนอื่นทำงานปกติ ย้ายข้อมูลระหว่างเครื่องด้วยไฟล์สำรองหรือรหัสย้ายเครื่อง
- ถ้าเลือก **"รวมกัน"** ตอนสองเครื่องชนกัน รายการที่เคยลบในเครื่องใดเครื่องหนึ่งอาจกลับมา
- ส่งออก Excel/PDF ถูกปิดไว้ (ดู `js/legacy/README.md`)
- ทดสอบบน Chromium บนคอมพิวเตอร์และจอมือถือจำลอง **ยังไม่ได้ทดสอบ** บน iPhone/Safari จริง และกับระบบซิงค์จริงของ Claude
