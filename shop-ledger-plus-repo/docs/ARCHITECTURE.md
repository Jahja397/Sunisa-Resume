# สถาปัตยกรรมโค้ด

## ภาพรวม
แอปเป็น **classic scripts** หลายไฟล์ที่แชร์ global scope เดียวกัน (ไม่มี module/bundler)
`index.html` โหลด `css/style.css` แล้วโหลด `js/*.js` **ตามลำดับเลขหน้าชื่อไฟล์ — ห้ามสลับลำดับ**
เพราะไฟล์หลังใช้ตัวแปร `const/let` และฟังก์ชันของไฟล์ก่อนหน้า (และ HTML ใช้ `onclick="fn()"` เรียกฟังก์ชัน global)

## โมเดลข้อมูล (เก็บใน localStorage)
| key | เนื้อหา |
|---|---|
| `ledger` | `[{id,type:'in'\|'out',amt,cat,note,date:'YYYY-MM-DD', sid?,rs?,pid?,q?,did?,demo?}]` |
| `plus` | `{prods:[{id,name,cost,price,stock,min}], sales:[{id,lid,pid,name,qty,rev,cost,date,cr?,did?}], debts:[{id,k:'r'\|'p',who,amt,due,paid,paidAmt?,sale?,item?}], goal, ign}` |
| `lang`, `syncOn`, `syncH`, `syncCH`, `syncAt`, `prevState`, `prevAt`, `sl_orphan_skip` | ภาษา, สถานะซิงค์, สำเนาก่อนการเปลี่ยนล่าสุด (ไว้ย้อนกลับ) |

**ความเชื่อมโยง:** รายการขายจากปุ่ม "ขาย" มี `sid` (→ `sales.id`) และ `sales.lid` (→ ledger id) · **ขายเชื่อ**: `sales.cr=1` + `sales.did`↔`debts.sale` (ไม่มีรายการบัญชีจนกว่าจะชำระ) · หนี้ที่จ่ายบางส่วนใช้ `paidAmt`, ยอดคงเหลือ = `rem(d)` ·
เติมสต็อก `rs:1,pid,q` · ชำระหนี้ `did` (→ `debts.id`) · ข้อมูลตัวอย่างมี `demo:1`
รายการเก่าที่ไม่มีลิงก์จะถูกจับคู่ให้โดย `migrate()` ตอนเปิดแอป

## ซิงค์คลาวด์ (เฉพาะใน Claude Artifact)
เอกสารที่ `data/users/<uid>/`: `meta` = `{n,h,t,v}` และ `p0..pN` = `{s: base64 chunk}` (เอกสารละไม่เกิน 256 KiB เลยแบ่งก้อนละ ~120 KB ก่อนแปลง base64)
กลยุทธ์: เครื่องที่ไม่มีการแก้ไขจะดึงของคลาวด์, ถ้าแก้ทั้งสองฝั่งจะถามผู้ใช้ (`mergeState` รวมตาม `id`)
ข้อควรรู้: การรวมอาจทำให้รายการที่ลบไปแล้วกลับมาได้ (ไม่มี tombstone)

## ข้อตกลงสำคัญในโค้ด
- ตัวเลขจากช่องกรอก **ต้องผ่าน `pn2()` เสมอ** ห้ามใช้ `parseFloat` ตรงๆ
- ข้อความจากผู้ใช้ที่ใส่ใน `innerHTML` **ต้องผ่าน `esc()`**
- วันที่เก็บเป็นสตริง `YYYY-MM-DD` และอ่านด้วย `pd()` (เลี่ยงปัญหาโซนเวลา) · `todayS` เป็น **getter** (คำนวณใหม่ทุกครั้งที่อ่าน แคช 1 วินาที) ห้ามประกาศเป็นค่าคงที่ เพราะแอปอาจเปิดค้างข้ามเที่ยงคืน
- วันที่ในอนาคตถูกปฏิเสธด้วย `badDate()` · ยอดขายสำหรับเป้าหมาย/จุดคุ้มทุนใช้ `salesSum()` ไม่ใช่ `sum(...,'in')`
- ลบข้อมูลต้องเรียก `rmLed/rmSale/rmDebt/rmProd` (หรือ `askDel`) ไม่ใช่ `data.filter` ตรงๆ เพื่อไม่ให้ข้อมูลหน้าอื่นค้าง
- ถ้าเพิ่มไฟล์ JS ใหม่ ให้เพิ่ม `<script>` ใน `index.html` ตามลำดับ (build-single อ่านลำดับจาก index.html)

## การลบสินค้า
ลบสินค้า = ลบเฉพาะตัวสินค้า (`rmProd`) ประวัติการขายและรายการบัญชีเดิม **เก็บไว้** เพื่อไม่ให้กำไรย้อนหลังเปลี่ยน ส่วนการลบรายการขาย/เติมสต็อก/ชำระหนี้ยังเป็นแบบลูกโซ่ตามเดิม (คืนสต็อก ลดยอดที่ชำระ ฯลฯ)
